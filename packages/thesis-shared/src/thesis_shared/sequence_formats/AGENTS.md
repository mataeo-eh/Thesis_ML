# Sequence formats contract

## Purpose

- Own framework-neutral presentation of serialized replay records for both experimental arms. The first implemented new path is an inspection-only joint pretraining preview; neither training pipeline consumes it yet.
- `PRETRAINING_PIPELINE.md` (repository root) is the human-readable specification of this format: stages, the within-timestep ordering rule, vocabulary layout, grammar, packing, and the per-arm input/target split. Keep it synchronized with any change here.

## Ownership

- `bpe.py`: deterministic content-ID BPE shared by the preview and corpus study, exact decoding, ranked merge provenance and expanded vocabulary export. `ContentBPETrainer` owns the transactional SQLite pair index (memory for previews, scratch disk for corpus fitting); `encode_ids` owns fast ranked encoding of one content-only word; `from_artifact` validates frozen tokenizer reloads. It has no framework dependency.

- `types.py`: immutable tokens, `JointReplay` inputs, `WindowSegment` spans and `SequenceWindow` results with both arms' masks as plain tuples; owner/timestep/replay fields are inspection metadata, not model features.
- `common.py`: perspective validation, structural tokens, and canonical per-owner record selection.
- `unconditioned_joint.py`: `[SELF] content [ENEMY] content [DELIMITER]` per timestep (including empty player blocks, with the ascending-token-ID check), the five-token `[BOS] [SELF] race [ENEMY] race` replay header, and the four-token outcome footer.
- `preview.py`: few-replay loading and readable exports. `scripts/preview_sequence.py` is its thin CLI.
- `../data/window_policies/unconditioned_joint.py`: contiguous whole-timestep budgeting over an ordered replay stream, a header per segment, a footer closing every segment, END only at actual replay end, and optional replay packing.
- `../vocab/sequence_vocabulary.py`: explicit format selection and the ownership/race-token overlay without shifting legacy IDs.

## Local Contracts

- Within each player block, content tokens are in ascending content token ID. This equals `serialize_snapshot` order (entities by Token_Dictionary source ID = SC2 unit type ID, then upgrades/research), because content IDs are assigned in source-ID order. `iter_joint_timesteps` raises if it is violated. Changing this order is a grammar change and must update `PRETRAINING_PIPELINE.md`.
- The joint vocabulary appends `[SELF] [ENEMY] [PROTOSS] [RANDOM] [TERRAN] [ZERG]` after all content IDs (297 IDs with the current dictionary). All four race tokens are always present, even when a corpus sample never uses one. Races come from replay metadata `players.<p>.race`; unknown values fail.
- Every replay segment opens with `[BOS] [SELF] <self race> [ENEMY] <enemy race> [DELIMITER]` and closes with `[SELF] self-outcome [ENEMY] enemy-outcome`, followed by `[END]` only at actual replay end. `[END]` is this format's end-of-sequence marker; `[EOS]` is unused.
- With `pack_replays: true`, the space after one replay's `[END]` is filled with the next replay's segment when its header, opening delimiter, at least one whole timestep, and footer fit. Otherwise the window closes. The rest of a replay continues in the next window under a fresh header. Replay order must be deterministic and within one split. Each window records its segments so an arm can choose document masking or per-segment positions; that choice is not made here.
- Diffusion clamps the window's first five positions (BOS and the leading race header) by POSITION; they are unscored. Later packed headers remain mutable and scored, matching unconditional sampling. AR scores every position except 0. The intended joint diffusion policy allows every vocabulary ID as replacement, including MASK/BOS/EOS/race tokens. It is recorded in preview metadata but not yet integrated into the production corruption/prior/sampler.

- Preview `tokenizer: atomic|bpe` is selectable; atomic remains the default, including older preview YAMLs. `bpe_min_occurrences: 3` stops fitting when no current adjacent pair occurs at least three times. Counts include overlapping pairs; replacements are left-to-right non-overlapping. Frequency ties use ascending token-ID pairs. There is no vocabulary-size cap.
- All canonical content IDs, including entities and upgrades/research, may merge with each other. Structural IDs (PAD/MASK, BOS/EOS, outcomes, ownership, race and delimiters) are hard boundaries; owner/timestep changes also break spans. Compound IDs append after the full base vocabulary. Base IDs and structural tokens never change.
- Fit on every selected replay once, both owners in one perspective, before re-windowing compressed whole timesteps with the same policy. The BPE profile selects one replay. The threshold applies at merge selection, not to final compound usage after subsequent merges. A learned merge may be applied even to a rare span during encoding.
- BPE exports under `scripts/output/sequence_preview/bpe/` include the re-windowed first sequence, `before/`, `same_window_bpe/`, `comparison.json`, and `bpe_vocabulary.json` (all base IDs, ordered merges, atomic expansions, and tokenizer identity). Compare identical spans separately from increased window coverage. Full-replay counts include one header/delimiter/footer/END (11 tokens) per replay, not repeated window overhead. Verify exact token/owner/timestep decoding across every selected replay.
- Tokenizer identity includes base vocabulary, allowed IDs, threshold and ordered merge rules; a vocabulary-name hash alone cannot identify BPE semantics. This replay-fitted vocabulary is in-sample debugging evidence only. Full fitting/tokenization/windowing/manifests belong on cloud compute; production fitting must use training replays only after replay splitting and freeze the tokenizer for dev/test and both arms. The separate `scripts/tokenizer_study.py` and user-operated OSCER handoff implement corpus vocabulary fitting/evaluation only; training adapters and manifests remain unimplemented for this path.

- The corpus study treats one owner's content at one timestep as one word and uses both owners once, before perspective expansion. One shared vocabulary spans Protoss/Terran/Zerg languages for a generic AR LLM trained from scratch; metadata Random resolves from an unambiguous first-timestep starting worker/townhall or fails (the reserved base ID stays allocated). `config/tokenizer_study.yaml`, validated in shared `config.py`, owns targets through 65536, a 32768 comparator, and default `multilingual_savings` selection: smallest vocabulary preserving the configured share of best observed dev savings overall and for each race separately; all three languages must occur in train/dev. Optional `reference`/`dev_savings` rules are explicit alternatives. Report per-race content compression/fertility and vocabulary-cost indicators without claiming model quality or measured throughput. Test counts are measured only after selection. Content IDs remain reversible and all base IDs remain allocated; no final-usage pruning. Exact full-stream counts use content plus `3*T+11` and exclude repeated window framing/padding. Scratch fitting stores are bound to corpus, source, vocabulary and settings identities.

- New preview defaults are declared in `config/sequence_preview.yaml`; missing/unknown format fails before replay I/O. Existing conditioned training remains in its original entry points. Selecting the conditioned format in the new preview fails explicitly rather than silently producing a joint sequence.
- Reuse `serialize_snapshot`: preserve entity-presence rules, upgrades, ordering, and all recorded timesteps. No fog, feature MLP inputs, time features, or conditioned input region in joint pretraining.
- The joint vocabulary spells existing ID 5 `[LOSE]`; the conditioned vocabulary retains `[LOSS]`. Swap footer ownership and outcome, and header ownership and race, together when changing perspective. All four footer positions remain scored.
- Joint windows are unpadded, at most the declared budget (minimum 11). Never split a timestep. Oversized individual timesteps fail explicitly.
- Metadata features must not be supplied to either arm during unconditional pretraining. Race is the single exception: it enters as vocabulary tokens in the header, not as a feature. Reintroducing other metadata requires an explicit observed-input or generated-feature design. AR teacher-forcing does not make unavailable inference-time metadata legitimate input.
- No inference-time rule forces complementary predictions: training scores both ownership markers and both outcomes so the model can learn the relationship. Recorded label validation is data validation only. The second outcome can use the first under causal teacher forcing; report that distinction when interpreting forecasting accuracy. Outcomes never precede entity targets in a segment.
- Never generate manifests, statistics, model weights, or processed replay arrays from the preview. Write only below `scripts/output/` and include no absolute paths in exports.
- Production integration still requires explicit format/checkpoint identities, both-perspective expansion, split-respecting replay order, masks/padding, loss taxonomy, decoder, full-vocabulary prior/corruption/renoising consistency, and both arm adapters. Do not pass the joint overlay or its BPE expansion to the legacy pipeline.

- Text-only display: each merged token is one bracketed, fully expanded atomic-name list, e.g. `[scv scv marine]`. Each segment's `[BOS]` is shown as `[BOS | <replay>]`; delimiters introduce one-based replay timesteps (`[DELIMITER 1]`); each segment's final delimiter labels replay/window end after its last timestep. CSV IDs, metadata and sequence vocabulary remain unchanged by display formatting.
