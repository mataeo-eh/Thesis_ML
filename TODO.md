Three decisions worth recording: (1) accuracy and F1 are reported per canvas state and never pooled, because a pooled number is dominated by positions whose canvas token already equals the target and so tracks the sampled corruption level rather than the model; (2) micro-F1 was dropped as redundant -- with one prediction per scored position it equals accuracy exactly -- so the F1 column is macro over the token vocabulary, which is also the number that falls when the model collapses onto common tokens (see the token-frequency item above); (3) `bits_per_token` comes from a separate UNWEIGHTED cross-entropy accumulator, not from `train_loss`/`dev_loss`, because those are the class-weighted objective and exponentiating them is not a perplexity of any distribution. `perplexity` is exactly `2 ** bits_per_token`. Both are comparable across models sharing splits and corruption schedule, and are NOT the same quantity as an autoregressive LM's next-token perplexity -- true "generative perplexity" would need a stronger reference model to score samples against, which does not exist for SC2 canvases.
