Summer 2026: I spent the summer getting the github repo and local directory set-up and ready to begin doing the real research and development for my thesis project. I had done a lot of bug fixes during the end of the spring 2026 semester and early in the summer. I ensured that my objective was learnable for the model with the representation I was using by doing 'overfitting' tests; trying to intentionally let the model overfit the data. This led to needing to make some changes. I learned that the model needed a token to anchor on to make the start of the output canvas clear in the context window. I used EOS (End Of Sequence) and BOS (Beginning Of Sequence) tokens for this. I also ran a full training run with a 30m paramater size model to have a 'base' model going into the semester. This model achieved a good CE loss of ~0.200 overall. However, it struggled with rare content token prediction and suffered heavily from sequence alignment. My first steps to take starting into the school semester and beginning the actual thesis research hours course, will be to run a small size ablation test, testing 2 models smaller, and 2 larger, for 3 learning epochs. This will see if a larger model can help overcome the current sequence alignment problem, or just in general perform better on the current dataset. The next step will be to test different methods for solving the sequence alignment problem. I also did a small ablation test that showed that the model can use a frozen KV cache for the clamped input and only need dynamic bidirectional attention over the output canvas for roughly the same performance but an increase in speed. I will need to run this test again on the resulting model after testing throughout the year before freezing it as final implementation. But this would reduce the memory and compute cost of transformer attention.
8/24-8/31: This week was primarilly spent working on the output visualizations test suite. Having a way to actually test the model on inference conditions, and be able to visualize its outputs and compare it to known ground truth. It can be tested on the held-out test split as the primary method. I also did a few tests on the training dataset out of curiosity. These visualizations confirmed the sequence alignment problem. They also confirmed the model struggled to predict rare content tokens. Such as late context 'tech buildings'. These visualizations also illuminated a bug in the sampler code that allowed for tokens to be frozen on the final output canvas that did not win the final argmax of the models output predictions. The rest of the week was spent on architecting and setting up the size ablation test. Also, I began thinking of ways to address the sequence alignment problem. An examination of the models output logits around the sequence positions where tech buildings should have been showed that the model was assigning a non-trivial amount of liklihood to tech buildings, and to the correct tech buildings. But these correct predictions were being drowned out by other tokens. My working hypothesis is that the diffusion model is sensitive to any insertion/deletion. I think this caused it, during training, to struggle to learn when and where to predict tech buildings confidently, especially towards the end of context. Especially when working with atomic tokens and having to essentially 'count' perfectly across hundreds to thousands of tokens in order to actually correctly predict the placement of rare tech buildings.
8/31-9/6: I have started running the size ablation test running as many steps as I can overnight or while I am gone for school and work. I expect this to take 1-2 weeks at the current rate only having access to running it locally on my desktop. I am also conceptualizing implementations to test for fixing the sequence alignment problem. My current hypothesis is that even the largest model from the size ablation test will not be able to overcome the full sequence alignment problem thus requiring a hand-crafted solution. I have 2 ideas I think are promising. The first, is to use a BPE style tokenizer to reduce the burden of 'counting' the model has to do. It will essentially be a trade of larger vocabulary size for fewer output tokens required to achieve the same semantic output. This is what I will reach for first, and depending on its efficacy, I can then look at implementing auto-regressive block outputs instead. Where each block is generated via the diffusion process, but then blocks are frozen AR style and generated in sequence to reach the desired context window size. This would give the model 'teacher forcing' type blocks for every block after the first in the sequence. Sort of off-setting the cost of the sequence alignment problem during training. The idea being to better enable the model to learn the sequences and get stronger structural signal for predicting rare content tokens in the proper places. But this would be secondary to testing a BPE-tokenizer enhanced vocabulary dictionary first.
